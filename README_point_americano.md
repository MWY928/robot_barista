# 点位路径美式集成

入口：`point_americano.py`。默认只离线检查，不打开串口、不连接机器人。
使用现有解释器 `/home/iaii/.conda/envs/cr/bin/python`，在本目录运行脚本。

- 无参数：校验三份路径、Tool/User、路径衔接及默认美式配方，打印预览。
- `--execute`：明确允许真实运动、落杯和出品（本次开发未执行）。
- `--speed 10`：全局速度百分比 1–100，默认取配置。
- `--continuous --radius 5`：复用 `point_path` 连续模式；中间点可被绕过，必须确认圆角避障空间。
- `--cup-timeout 30 --coffee-timeout 180`：设备阶段有限等待时间，含请求。
- `--config PATH`、`--cup-port PATH`、`--coffee-port PATH`：覆盖配置或串口路径。

## 固定顺序

1. 回放 `point_paths/pick_cup.json`。
2. 落一个杯；设置成功回复不视为完成，继续查询状态直到 `work_state == 0`。
3. 回放 **`point_paths/cup2coffee.json`**。
4. 调用 `CoffeeMachine.do_product(5)`，使用当前实现的全部默认美式参数及 MP0。
5. 请求之后约每秒查询一次，必须先观测 MP0 低四位 `0`，再观测 `2`。
6. 等待 2 秒，再回放 `point_paths/coffee2window.json`。

## 完成语义与限制

- 落杯完成 API 已按源码核实：`dispense_and_wait()` 内部也是查询 `work_state == 0`，没有独立完成帧。集成显式实现同一状态条件，使用单调时钟并检查故障；不把 `dispense()` 的成功当完成。
- 原落杯 `_transact()` 默认重发三次；本脚本局部子类强制只发一次，不改变既有驱动。咖啡驱动本身不自动重发。超时、拒绝、协议错误均中止，不执行后续运动。
- 初始就为 `2` 不会使咖啡等待成功；若轮询漏过短暂的 `0`，会保守超时，不猜测完成。状态 `1` 不是本流程的完成条件。
- 落杯待机状态不能证明杯子已可靠进入夹具，咖啡状态转换也不能证明杯中实际液量。必须人工完成现场工艺与安全验证。
- 所有路径与配方在任何硬件动作之前校验；回放时仍复用原来的实时起点、坐标系检查及运动超时/异常停止。文件在运行中不得修改。
- 默认配方是现有代码的示例值（40 ml 咖啡水、120 ml 补水、混合温度 70、顺序 1），不是厂商推荐配方，要求机器为摄氏温标。
- 设备阶段限制串口读写与协议等待时间；它不是操作系统硬实时保证，串口打开、文件系统持久化等系统调用可能受系统影响。
- 中止不会自动重发、重新出品或自动回撤；关闭串口不等于停止设备。运动错误由原 `point_path` 处理；设备等待失败时请人工核实状态，必要时使用现场急停。

`tests/test_point_americano.py` 使用 mock 覆盖顺序、低四位状态、必须先 0 后 2、落杯状态等待、超时后无下一段运动、单次发送、预检失败与默认预览不连接设备。
